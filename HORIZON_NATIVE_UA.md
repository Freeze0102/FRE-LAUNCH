# FRE LAUNCH — Horizon як окрема Rust-збірка в бібліотеці

## Поточна реалізація у `main`

- **Створити збірку → Horizon (Rust)** відкриває майстер у FRE LAUNCH.
- Офіційний перевірений компонент встановлення Horizon завантажується
  автоматично; не потрібно вручну завантажувати ZIP.
- Через офіційний інтерфейс оновлень/підготовки встановлюється справжній
  `horizon-client.exe` та готуються ресурси з власної легальної копії
  Minecraft Java 26.3.
- Кнопка «Створити окрему збірку» викликає команду створення реального
  Horizon-профілю; його ID, назва та вибрана версія беруться з офіційного
  локального списку, а не з фальшивого localStorage.
- **Головна бібліотека FRE LAUNCH** показує Rust-профілі окремим розділом
  поряд із Java-збірками. Відображається назва, версія, стан ресурсів,
  кнопки «Грати» і «Налаштувати». Оновлюється після створення чи підготовки.
- «Грати» тепер запускає **безпосередньо `horizon-client.exe`** з аргументом
  `--resources`, робочою папкою й `HORIZON_HOME` потрібного профілю.
  Виклик `horizon-launcher play --instance` для цієї кнопки більше не потрібен.
- Звичайний Horizon helper використовується **тільки всередині** FRE LAUNCH
  для встановлення, створення профілів, оновлень, підготовки ресурсів і за
  потреби поновлення авторизованої сесії. Жодне друге вікно для звичайного
  запуску гри не відкривається. Ручне вікно входу залишено в «Додатковому».

## Перший запуск Minecraft Rust без ручного імпорту (зміни 03.11.2026)

Для **вбудованих FRE Rust-профілів** створення збірки або перше натискання
«Грати» тепер викликає підготовку ресурсів на власному комп'ютері:

1. FRE LAUNCH перевіряє власний кеш та раніше підготовлені ресурси Horizon.
   Якщо вони є — не завантажує їх повторно.
2. Якщо готових файлів немає — встановлює перевірений за SHA-256 офіційний
   допоміжний Horizon CLI, за потреби встановлює ігрову версію та запускає
   `prepare` для вже встановленої Minecraft 26.3.
3. Якщо локальної гри недостатньо, запускає `prepare --download`:
   **офіційний Horizon** перевіряє Microsoft-акаунт власника Java Edition
   та завантажує відсутні файли **з Mojang**, перевіряючи контрольні суми.
   За відсутності авторизації є кнопка «Увійти у Horizon через Microsoft».
4. Після успішної перевірки ресурси копіюються до окремого кешу
   `fre-rust-minecraft/prepared`, який використовують усі нативні збірки.
   Кеш не перезаписується автоматично, світи не змінюються. Повідомлення
   про етапи встановлення показують **реальні етапи**, а не вигадані відсотки.

У вкладці **Вміст** нативного Rust-профілю доступний пошук у **власному
каталозі модів Horizon** з установленням, переліком установлених модів
та видаленням через офіційний CLI. Для кожної збірки використовується
`horizon-mods/`. Стару папку `mods/` не видаляємо і не переносимо —
звичайні Fabric/Forge JAR не стають сумісними з нативним рушієм.
Нативні моди, які потребують окремого компілювання, не обіцяємо
автоматично активувати як звичайні пакети.

**Перевірка:** зміни внесено в шаблони коду та перевірки зв'язків.
Повний Windows build, авторизоване завантаження реальних Minecraft
ресурсів і запуск світу не підтверджені — перед публічним оновленням
потрібний локальний end-to-end тест на Windows. Приватні ресурси Mojang
у GitHub / публічний інсталятор не додаються.

## Де лежать файли

Поки використовуються сумісні з офіційним Horizon папки, щоб **не загубити
наявні світи або створені раніше профілі**. На Windows за замовчуванням:

- Гра: `%APPDATA%\horizon-launcher\versions\<тег>\horizon-client.exe`
- Підготовлені ресурси:
  `%APPDATA%\horizon-launcher\versions\<тег>\.local\horizon-client\26.3`
- Збереження за замовчуванням: `%APPDATA%\horizon`
- Окремі збірки: `%APPDATA%\horizon\instances\<slug>`

Це **не перенесення** даних з Horizon до FRE LAUNCH: спільний сумісний формат
дає змогу бачити раніше створені власні збірки. Rust-профілі не додаються як
Java-профілі до SQLite Modrinth, бо в них інший формат гри і модів.
Не змінюйте ці папки вручну, поки гра запущена.

## Межі інтеграції

- Rust-клієнт Horizon — стороннє відкрите ПЗ. FRE LAUNCH не обходить
  ліцензування Minecraft та не вбудовує його закриті ресурси.
- Вхід через Microsoft усе ще може потребувати допоміжних офіційних
  компонентів Horizon: це не власна реалізація Horizon-авторизації.
- Поточна інтеграція показує окремий розділ у бібліотеці, **не** інтегрує
  Rust-збірки у внутрішнє сортування/групування Java-екземплярів.
- Налаштування обкладинок Rust-профілів та перенос їх у повністю власну
  директорію ще не зроблені: це окремі сумісні наступні кроки.
- Статична перевірка з'єднань фронтенда, Rust-команд і перекладів пройшла;
  **повну нову Windows-компіляцію та реальний запуск гри з цими змінами не
  виконано**. Поки це зміни у вихідному коді, не готовий EXE.

## CurseForge

У каталозі API-поле прибране в «Додатково» для чистішого інтерфейсу.
Власний схвалений ключ застосунку (переданий через
`FRE_CURSEFORGE_API_KEY`) дозволяє здійснювати пошук без ручного введення
на кожному комп'ютері. **Ключ чужого лаунчера не копіюється.** Без
схваленого ключа доступний пошук через офіційний сайт CurseForge, а не
фіктивна внутрішня видача. Для повної публічної інтеграції слід отримати
офіційний дозвіл.

## Як перевірити локально без GitHub Actions

```powershell
# У ПОВНОМУ поточному каталозі FRE LAUNCH:
.\FRE-MODRINTH-LOCAL.ps1 -BuildWindows
```

Не використовуйте `FRE-LAUNCH-LOCAL.cmd` для цього форка: він належить
старій окремій React-реалізації. Збірка потребує Node 24.15+, pnpm
12.11.2+, Rust MSVC, C++ Build Tools та відповідних інструментів Tauri.

Після встановлення тестової збірки створіть Horizon-профіль, переконайтеся,
що він з'явився в бібліотеці, а «Грати» запускає саме
`horizon-client.exe`. Перевірте логи, створення окремого світу та повторний
запуск після закриття FRE LAUNCH. Спершу зробіть копію наявних світів.

**GitHub Actions цими змінами не запускалися.**
