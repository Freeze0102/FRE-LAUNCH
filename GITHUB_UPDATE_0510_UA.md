# FRE LAUNCH 0.5.10 — GitHub Windows Build і оновлення в лаунчері

## Реальний стан
- Вихідний код каналу: **0.5.10**.
- Останній опублікований реліз на момент підготовки: **0.5.9**.
- **0.5.10 не опублікований**. Самі коміти в `main` не встановлюють
  нову програму на ПК. Потрібен успішний Windows-білд, перевірений
  інсталятор та чинний підпис.
- Старий `Windows Build` збирає іншу, React-версію. Не використовувати
  його артефакти для оновлення Vue/Rust.

## Що зроблено
- **FRE LAUNCH Vue Rust Windows Update**:
  `.github/workflows/fre-modrinth-rust-update.yml`.
  Збирає закріплений MIT Rust-клієнт, справжній Vue/Tauri форк, перевіряє
  TypeScript, створює NSIS, сканує обидва виконувані файли й інсталятор
  Microsoft Defender, тестує встановлення в окрему папку та початковий
  запуск. Перевіряє підпис. Завжди зберігає перевірені артефакти в
  **Artifacts**; **не** публікує без явного схвалення.
- **Publish reviewed FRE LAUNCH Vue Rust update**:
  `.github/workflows/fre-publish-reviewed-update.yml`.
  Не перезбирає Windows EXE, а завантажує артефакти конкретного успішного
  білду того самого коміту, звіряє SHA-256, Minisign, дані Defender і
  відсутність пропрієтарних файлів Minecraft. За явного схвалення
  створює GitHub Release з `latest.json` і після публікації виконує
  анонімний smoke-test каналу.
- Публічний реліз містить **лише відкритий MIT Rust-клієнт** — не
  приватні ресурси Mojang/Microsoft. Вони імпортуються в лаунчері
  локально з власної гри після перевірки Microsoft Java Edition.
  Ресурси можна перенести з раніше підготованої папки через меню
  **Minecraft на Rust → Імпортувати ресурси**; стара папка не видаляється.
- Підпис залишається **тим самим**, що у встановленому Vue/FRE LAUNCH
  0.5.9. Заміна ключа порушить автооновлення.

## Одноразове безпечне налаштування GitHub

Власник репозиторію має відкрити **Settings → Secrets and variables →
Actions → New repository secret** та додати
`FRE_TAURI_SIGNING_PRIVATE_KEY` — **вміст того самого
`.fre-update-keys/frelaunch.key`, яким підписано 0.5.9**.
Якщо на ньому задано пароль, додати захищений secret
`FRE_TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

**Ніколи не публікувати ключ у чаті, коміті, Issues, файлах Artifacts
чи скриншотах!** Не створювати нову пару замість старої. Якщо оригінальний
закритий ключ втрачено, безшовне підписане оновлення вже встановленого
клієнта стане недоступним.

## Порядок випуску — без старого Windows Build

1. Відкрити вкладку Actions → **FRE LAUNCH Vue Rust Windows Update** →
   Run workflow → branch `main`, `publish=false`. Успішний run дасть
   `FRE-LAUNCH-v0.5.10-Vue-Rust-Windows-REVIEW` у Artifacts.
   Відсутність ключа зупиняє workflow **до** дорогої збірки.
2. Перевірити EXE на окремій Windows VM, Microsoft-вхід, збереження
   Java-світів, створення Rust-профілю, імпорт власних ресурсів та
   запуск Rust Minecraft. Windows CI smoke не доводить сумісність
   Minecraft на реальному ПК і не замінює незалежний безпековий огляд.
3. **Лише після справжньої перевірки** задати repository variable
   `FRE_LAUNCH_SECURITY_APPROVED=true` в GitHub Settings → Secrets and
   variables → Actions → Variables.
4. Actions → **Publish reviewed FRE LAUNCH Vue Rust update** →
   Run workflow → ввести **run ID успішної нової Vue/Rust-збірки**. Сценарій
   перевірить, що цей білд зроблено з поточного `main`, підпис
   відповідає 0.5.9, а приватні Mojang-активи не вбудовано.
   Публікується `v0.5.10` без заміни старих релізів.
5. Після зеленого smoke-test встановлений Vue/FRE LAUNCH 0.5.9,
   який має діючий підписаний updater, зможе побачити **0.5.10**
   і показати дію оновлення. Якщо користувач досі запускає стару
   React-версію без updater, її доведеться один раз замінити вручну.

## Чого не можна стверджувати до нового run
Новий EXE ще **не** скомпільовано й не перевірено з цими змінами.
Немає підстав називати оновлення доступним користувачам без
публічного `v0.5.10/latest.json` і відповідного інсталятора.
Ніколи не завантажувати непідписаний Windows EXE як нову версію або
підміняти старі assets під тим самим тегом.
