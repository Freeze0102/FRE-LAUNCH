# Як перевірити найновіший FRE LAUNCH без GitHub Actions

Цей спосіб збирає **поточний код гілки `main` на твоєму комп'ютері**. Немає потреби чекати оновлення квоти GitHub Actions, платити за хвилини або публікувати неперевірений інсталятор.

> **Увага:** локальне компілювання не гарантує безпеки виконуваного файлу. Розслідування попереднього спрацювання Defender на v0.5.5 ще не завершене. Не відновлюй старий інсталятор із карантину, не вимикай Windows Security і не запускай підозрілі файли з правами адміністратора.

## Що треба встановити лише один раз

1. **Node.js 22** із [nodejs.org](https://nodejs.org/en/download) — має бути доступний `npm`.
2. **Rust (stable, MSVC)** з [rustup.rs](https://rustup.rs/) — має бути доступний `cargo`. Для Windows x64 потрібен `x86_64-pc-windows-msvc`.
3. **Microsoft Visual Studio C++ Build Tools** — під час встановлення познач **Desktop development with C++**, з MSVC і Windows SDK.
4. **Microsoft Edge WebView2 Runtime** (в Windows 10/11 часто вже встановлено).

Офіційна інструкція: [Tauri 2 — Windows prerequisites](https://v2.tauri.app/start/prerequisites/).

**Після встановлення інструментів закрий та знову відкрий термінал.** Для збірки FRE LAUNCH не потрібні права адміністратора.

## Найпростіший шлях — один файл

1. У репозиторії [FRE-LAUNCH](https://github.com/Freeze0102/FRE-LAUNCH) натисни **Code → Download ZIP**.
2. Розпакуй ZIP **повністю** в просту папку, наприклад `D:\FRE-LAUNCH-SOURCE`. Не запускай програму прямо з ZIP.
3. Запусти **`FRE-LAUNCH-LOCAL.cmd`** у цій папці.
4. Вибери **1**, щоб запустити останній код FRE LAUNCH у режимі тестування без інсталятора. Для цього вікно термінала має залишатися відкритим.
5. Вибери **2**, щоб виконати перевірку TypeScript, Rust-тести та створити новий **Windows EXE і звичайний NSIS-інсталятор** на своєму ПК. Скрипт нічого не встановлює та не запускає автоматично після збірки.

### Де результат

- Скомпільована програма: `src-tauri\target\release\fre-launch.exe`.
- Інсталятор для поточного користувача: `src-tauri\target\release\bundle\nsis\` — точна назва EXE залежить від версії Tauri.
- Ігрові файли й світи Minecraft **не зберігаються в цій папці**. Інсталятор і файли гри — різні речі.

## Як перевіряти нові зміни

Для нової версії коду з GitHub повтори **Code → Download ZIP**, розпакуй його й знову запусти `FRE-LAUNCH-LOCAL.cmd`. Або, якщо використовуєш Git, виконай `git pull origin main` у клонованому репозиторії.

Можна тестувати режимом **1** і не витрачати час на створення інсталятора після кожної дрібної зміни. Готовий EXE створюй режимом **2** тільки після успішного тестування.

### Якщо не запускається або є помилка

- `npm / node not found`: встанови Node.js 22 і перезапусти термінал.
- `cargo / rustc not found`: встанови Rust через rustup та MSVC toolchain.
- `link.exe / windows sdk / LNK... error`: перевір **Desktop development with C++** і Windows SDK у Visual Studio Installer.
- `WebView2` error: встанови runtime з офіційного посилання в інструкції Tauri.
- `TypeScript`, `cargo test`, `tauri build` error: скопіюй **першу конкретну помилку** з консолі та надішли в чат — це помилка коду або збірки, не потрібно обходити її антивірусними винятками.
- Попередження Windows Security: **не вимикай захист**. Збережи точний текст детекції й ідентифікатор нового файлу для розслідування.

Ми поки не підтвердили, що всі останні коміти компілюються на Windows. Саме для цього й потрібне локальне тестування. Краще спершу відкрити **режим 1** і перевірити головну сторінку, збірки, каталог і запуск Minecraft.
