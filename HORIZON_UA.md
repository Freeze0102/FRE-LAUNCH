# Horizon (Rust) у FRE LAUNCH 0.5.9

У **Створити збірку → Horizon (Rust)** тепер є покрокове налаштування замість
набору команд. Збережено темний дизайн, окремі збірки, точні теги версій і логи.

1. **Завантажити Horizon для Windows**. FRE LAUNCH завантажує офіційний
   `horizon-launcher` 0.2.33 і перевіряє SHA-256 архіву та EXE. Вручну
   розпаковувати ZIP не потрібно. Якщо Horizon уже є, натиснути
   **У мене вже є horizon-launcher.exe**.
2. **Установити Horizon**. Завантажиться рекомендована гра Nightly; конкретний
   тег можна вибрати в розгорнутому розділі **Інші збірки, версії та діагностика**.
3. **Підготувати ресурси**. Потрібна Minecraft Java 26.3, запущена хоча б раз.
   Якщо Horizon її не знайде, вибрати **папку тієї збірки 26.3**, а не EXE
   Minecraft або папку світу. Можна повернути автоматичний пошук.
4. Вибрати збірку зі списку й натиснути **Грати в Horizon**. Для першого запуску
   вже є стандартна збірка Horizon; створювати нову та вводити її назву вдруге
   не потрібно.

Кнопка гри доступна після перевірки ресурсів саме вибраної версії. Якщо збірка
закріплена за старішим тегом, перевірка й підготовка стосуються цього тега.
Після кожної операції стан зчитується повторно з офіційного CLI.

## Акаунт та ресурси

У перевіреному CLI 0.2.33 команда Play вимагає Microsoft-акаунт, який володіє
Minecraft Java. Вікно офіційного Horizon відкривається кнопкою
**Відкрити Horizon / увійти в акаунт**. FRE LAUNCH не переносить туди свої
токени, не обходить перевірку ліцензії й не обіцяє працездатний вхід, якщо
конкретний випуск Horizon не налаштував свою Microsoft-інтеграцію.

Деякі тексти сайту Horizon про акаунти відстають від цього випуску. Для
контракту перевірено саму Windows EXE 0.2.33, її `--help` та
[README цього release commit](https://github.com/horizon-rust/horizon/blob/c1f4a7c1968b035596d0cae9985fa154cb5bda41/launcher/README.md).

Якщо Minecraft 26.3 ще не встановлена, її слід встановити й один раз запустити
у звичайному Minecraft launcher. Власний офіційний Horizon також має підготовку
через Mojang для авторизованого власника гри; вона залишається у його вікні.

## Як працює інтеграція

- Офіційні команди без shell: `instance list --json`, `instance create`,
  `versions --installed --json`, `install`, `prepare --minecraft/--version`,
  `instance version`, `play --instance`, `logs --lines 120`.
- У списку Rust-збірок не показуються Java-профілі, створені самим Horizon.
- Download bootstrap має фіксований офіційний URL, розміри й два SHA-256.
  З архіву читається тільки один очікуваний EXE; довільні шляхи не розпаковуються.
  Запис атомарний, наявний змінений EXE не перезаписується.
- Копія лаунчера зберігається у каталозі даних FRE LAUNCH
  `horizon-launcher/0.2.33`; світи, версії й акаунти гри керуються Horizon окремо.
- Старі ручні можливості залишилися в **Інші збірки, версії та діагностика**:
  створення окремих збірок, точний тег, призначення версії, оновлення списку й логи.
- Паролі й токени Horizon не передаються фронтенду FRE LAUNCH. Логи читаються
  локально й автоматично нікуди не надсилаються.

## Перевірено 01.11.2026

Офіційний Windows ZIP 0.2.33:
`590aa11b6d653ac58dcb1bd3149d22d485d2bc215f4eb912b4c79a710ee7f571`.

Перевірено розмір/хеш, Microsoft Defender, фактичні help/JSON-списки,
завантаження гри `nightly-2026-11-01-8c02c0b`, а також створення збірки через
**новий Rust backend і справжню офіційну EXE**. Усі тестові каталоги винесено в
`.audit/horizon-official` через офіційні HOME overrides.

Підготовка з навмисно порожньою тестовою Minecraft-папкою коректно повернула
exit 1 та повідомлення про відсутню 26.3. Готовність не була оголошена.
Позитивна підготовка з ліцензійними ресурсами, Microsoft login і запуск самого
ігрового рушія цим тестом не підтверджуються.

Окремий browser preview справжнього Vue-компонента перевірив переходи між
кроками, блокування недоступних дій і кнопку гри після підготовки; IPC у цьому
preview імітується. Це відокремлено від тесту справжнього native CLI.

Результати Python/TypeScript/Rust, білду та updater — у [AUDIT_UA.md](AUDIT_UA.md).
Встановлений FRE LAUNCH, користувацькі профілі та світи для тестів не змінювалися.
GitHub Actions не запускали.

Horizon — стороння гра на Rust. FRE LAUNCH керує його лаунчером, але не
виправляє рушій і не перетворює Java JAR-моди на Rust-моди.
Офіційна інструкція: https://playhorizon.dev/docs/install .
