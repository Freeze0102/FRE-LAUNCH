# Аудит поточного форка FRE LAUNCH — 01.11.2026

Доповнення цієї ж дати: реалізовано власний updater для Vue/Tauri-форка;
результати наведено в кінці звіту та в [UPDATES_UA.md](UPDATES_UA.md).

Актуально: strict TypeScript 308 → **0**, повний локальний Windows build **0.5.8
успішний**; створено й перевірено підписаний NSIS. Defender не виявив загроз
у нових EXE та інсталяторі. Пакет залишається **SECURITY-REVIEW-ONLY**, без
публічного релізу. Розділи з попередніми блокерами нижче є історією аудиту;
остаточні результати, хеші й відкриті питання наведено в кінці.

Об'єкт перевірки: `main`, початковий коміт `38213c807c8d07644a7a45d6ff22bb24107e3c00`,
генератор `scripts/modrinth-fork` і Modrinth
`4ccf4d51804627cd0687ce7dfd5004f20c267acc`.
Стара реалізація React у корені — окремий застосунок; результати нижче
не є підтвердженням її працездатності.

## Виправлення

- CurseForge використовував `write_instance_file`, але цей pin навмисно
  забороняє файловому API запис у `mods/`. Тепер перевірений JAR імпортується
  через `add_project_from_path`: штатне сховище вмісту реєструє файл і надсилає
  подію оновлення. Світи не беруть участі в імпорті.
- API-ключ CurseForge передається тільки API. Заголовок `x-api-key` більше не
  потрапляє на CDN. Збережено перевірку дозволу автора й доступності проєкту;
  перевіряються ID мода/гри, версія Minecraft, loader, розмір, SHA-1,
  безпечне ім'я та HTTPS-домен. SHA-1 — задокументований алгоритм CurseForge;
  попереднє припущення про алгоритм API `3 = SHA-256` прибрано.
- Додано перевірку центрального каталогу JAR, CRC, шляхів записів і обсягу
  розпакування. Самого заголовка `PK` недостатньо.
- Повторний JAR/ім'я відхиляється до імпорту. Зміна версії/loader профілю під
  час завантаження, відкритий процес Minecraft, quarantined/shared-профіль
  також блокують імпорт. Одночасні CurseForge-імпорти серіалізовано.
- Пошук CurseForge відкидає відповіді попереднього запиту після зміни тексту,
  ключа, профілю або закриття компонента. Повідомлення встановлення називає
  профіль, у який справді надіслано команду.
- У каталозі Modrinth прибрано звернення до неіснуючого `browseBreadcrumb`
  та запис у readonly computed при скиданні контексту профілю; використано
  актуальне поле назви проєкту. Уточнено типи ID профілю та файлів діалогу.
- Horizon запускається через аргументи процесу без командного shell.
  Для службових команд stdin закрито, вивід обмежено 24 000 байт на потік,
  є таймаут 60 с для коротких операцій та 30 хв для install/prepare.
  Завислий службовий процес завершується; швидка помилка Play повертається
  в інтерфейс. Передавання керування CLI не оголошується успішним запуском гри.
- `prepare` підтримує вибір нестандартної папки Minecraft (`--minecraft`)
  та конкретної версії Horizon (`--version`). Для `latest` лишається штатний
  вибір офіційного CLI. Інсталяція версії в самому Horizon вибирає її глобально.
- Уточнено перевірку назв Unicode та тегів версій; відхиляються `.` і `..`.
  Вимоги авторизації залишаються за відповідним офіційним випуском Horizon.
- Генератор відхиляє інший pin і повторне застосування до готового дерева.
  Позначка готовності записується лише після всіх патчів. Невдалий патч
  перевірено окремим тестом. Незавершене дерево архівується перед повторенням;
  автоматичне рекурсивне видалення старих архівів прибрано.
- `Cargo.lock` детерміновано доповнюється вже зафіксованими `md5`, `sha1`
  і `zip`, без оновлення версій решти залежностей. Вказано потрібні можливості
  Tokio. Обидва Tauri-плагіни мають capabilities лише головного вікна.
- Виправлено типи локальних акаунтів/скінів та обробку `unknown` помилок.
  Розміри PNG перевіряються перед виділенням пам'яті для декодування;
  невдале збереження не видаляє попередній скін.
- Стандартний `vue-tsc --noEmit` перевіряв порожній references-only конфіг.
  `tsc:check`, `test` і `build` тепер перевіряють `tsconfig.app.json`;
  додано потрібні aliases, офіційні типи вже встановленого `vite-svg-loader`
  та бібліотеку типів ES2023 для API, які використовує pin. Підрахунок
  діагностик зменшився з 1600 у першій справжній перевірці до 308; це
  діагностики компілятора, а не кількість виправлених ігрових багів.

## Перевірки та межі результату

Локальне середовище: Windows x64, Node 24.22.1, pnpm 12.11.2,
Python 3.12.14/Pillow 12.3.0, Rust 1.95.0 MSVC, Visual Studio 2026.
Наявні залежності встановлено за незміненим `pnpm-lock.yaml` через
`pnpm install --frozen-lockfile`.

- Python: три тести, включно з повним застосуванням до **чистого реального pin**,
  ін'єкцією помилки, перевіркою готового дерева, повторного запуску та drift anchor.
- Vue: шість тестів реальних script setup/реактивності через зафіксовані Vue
  compiler/TypeScript; гонки пошуку, доступність проєкту, адресат встановлення,
  параметри prepare, повторний Play, помилки CLI та скидання каталогу.
- PowerShell: синтаксичний розбір сценарію; сам сценарій запуску встановленої
  копії не виконувався.
- Vite: окрема production-збірка інтерфейсу без TypeScript gate проходить.
  Це перевірка компіляції Vue/ресурсів, **не** успішний повний `build`.
- Windows Rust: `cargo check -p theseus_gui --offline` проходить для
  виправлених модулів і Tauri permissions. Першу спробу обмежувало локальне
  середовище MSVC (`LNK1114`); повтор у Developer PowerShell пройшов.
- Windows Rust/Tauri: п'ять тестів Horizon і п'ять CurseForge пройшли.
  Один ignored-тест — допоміжний дочірній процес для перевірки таймауту;
  сам timeout-тест його запускає.
- Ще два нативні тести бібліотеки пройшли: реальні UUID гостьових облікових
  даних Notch/Steve та відхилення некоректних/завеликих PNG. База користувача
  для цих тестів не ініціалізується.
- Strict TypeScript: **308 діагностик**. Кожна вказує на рядок, що лишився
  незміненим від pin (звірено зі source diff); це не доводить безпечність
  цих помилок для виконання. У CurseForgeBrowser, HorizonRustPanel,
  локальних акаунтах, Skins і Horizon wizard нових діагностик не залишилося.
- Живий Modrinth: v3 Search з `new_filters`, поле `name`, v2-версії файлів;
  пошук Fabric API для Fabric/Minecraft 1.21.1,
  вибір `0.116.17+1.21.1`, завантаження JAR 2 452 735 байт у пам'ять,
  збіг розміру та SHA-512. Файл у профіль не встановлювався.
- Живий Mojang: Minecraft 26.3, Java 25, метадані 114 бібліотек і 5147 ресурсів;
  перевірено SHA-1 client JAR, бібліотеки й ресурсу наявним smoke-сценарієм.

## Блокери

1. Справжній strict TypeScript check ще падає на 308 діагностиках ширшого
   upstream: зокрема InstallToPlayModal, спільні провайдери UI, moderation та
   застарілі типи utils. Їх не приховано через `any`, `skip` або `@ts-ignore`.
   Через це звичайний Windows build тепер чесно зупиниться на gate.
   Готовий NSIS/релізну EXE з цих змін не випущено.
2. Схваленого ключа CurseForge для живого пошуку/встановлення немає.
   Доступ до реального API, імпорт у тестовий профіль та запуск модифікованої
   гри не підтверджено. Обов'язкові залежності CF автоматично не встановлюються;
   CF-мод імпортується як локальний файл, без автоматичного оновлення з CF.
   Різні версії одного мода з різними назвами або з різних каталогів ще можуть
   конфліктувати. Попередня перевірка дублікатів не є загальною транзакцією
   з усіма іншими діями редагування профілю.
3. Офіційний бінарний Horizon, підготовка ресурсів, авторизація та рендеринг гри
   на цьому ПК не запускалися. Тестовий CLI перевіряє контракт аргументів,
   таймаути й обробку помилок, а не сам Horizon. Офіційна install-сторінка й
   актуальні коментарі CLI по-різному описують готовність входу Microsoft;
   інтеграція не обходить перевірок відповідного випуску.
4. Ігровий рушій Horizon не змінювався. Помилки сіна/нотного блока/вживання їжі
   не оголошуються виправленими без ігрових тестів і vanilla parity.

Встановлена користувацька EXE, її налаштування, профілі та світи не змінювалися.
GitHub Actions не запускалися; workflows залишаються ручними.

## Доповнення: власні оновлення FRE LAUNCH 0.5.8

Репозиторій тепер публічний; endpoint спрямовано на його GitHub Releases.
Код автоматично перевіряє оновлення після ініціалізації стану, завантажує
інсталятор і показує прогрес та «Перезапустити й оновити» у наявному дизайні.
Збережено ручне завантаження на лімітованій мережі. Додано повторні перевірки
після втрати мережі, повтор завантаження після помилки, захист від подвійних
натискань і скидання прапорця перезапуску після невдалого закриття вікна.
Повільний HEAD-запит розміру не затримує основне завантаження.

Upstream release-конфіг більше не використовує адресу/ключ Modrinth або їхній
Digicert. Cargo feature updater, Tauri plugin, capability та версії Cargo,
lockfile, frontend узгоджено. Замість широкого updater:default дозволено тільки
updater:allow-check. Власна Rust-команда перевіряє адресу конкретного випуску,
межу 256 MiB, повноту завантаження, Windows-заголовок і Minisign-підпис власним
ключем **перед** збереженням у PendingUpdateData. Підтримано лише prehashed ED
підписи. Черга використовує незмінні перевірені байти та штатний NSIS install
hook Modrinth/Tauri. Готове оновлення встановлюється при закритті; повторний
запуск запитується лише кнопкою користувача.

Приватний ключ створено лише локально в ігнорованому каталозі. Публічний ключ
зафіксовано в update-channel.json. Додано package-update.mjs для перевірки
реального Tauri-підпису через Node crypto та створення канонічних EXE/SIG,
latest.json, SHA256SUMS і нотаток. Автоматичної публікації цей помічник не робить.

## Доповнення: strict TypeScript 308 → 0 та локальний release build

Справжній `vue-tsc --noEmit -p tsconfig.app.json` проходить без діагностик.
Gate залишено у звичайному `build`; нові `any`, `as any`, `@ts-ignore` або
`@ts-nocheck` не додавалися. Кількість діагностик не є кількістю ігрових багів.

Виправлення збережено у перевірюваному наборі frontend-type-fixes.json та
feature_frontend_types.py, який застосовується після решти патчів до точного pin.
У разі drift перевіряються всі зміни перед записом, а вихід за source root
заборонений. Згенерований код 123 змінених/доданих файлів звірено з незалежною
підготовкою чистого pin, зі збереженням локального кешу компіляції.

Основні групи виправлень:

- Узгоджено спільні factory-функції TanStack Query та реактивний вибір запитів;
  залишено конкретні типи відповідей, callbacks і select. Типізовано читання
  кешу редактора game settings та діапазони ключів запитів.
- Виправлено DTO v2-залежностей Modrinth: project_id, version_id та file_name
  є незалежними nullable полями. Модалка встановлення розпізнає embedded файли,
  очищає попередній результат і відкидає застарілі відповіді після зміни версії.
  Без server project ID вона не закривається й не запускає встановлення.
- Виправлено клієнтські контракти встановлення, null для успадкованих параметрів
  профілю, тип результату розпакування та передачу типу в черзі встановлень.
- Виправлено запис у read-only computed під час переходу між профілями;
  виправлено ім'я instance_name у статусі друзів та відображення неназваних
  синхронізованих серверів. Обробник повідомлень приймає помилки Rust-рядки,
  структуровані помилки й null, не падаючи на error.message.
- Узгоджено Toggle/SegmentedControl, DOM refs, атрибути полів, tooltip API,
  обов'язкові menu labels, image editor/Fabric, текстури та формати повідомлень.
  Незнайомі теги не індексують властивості прототипу як переклади.
- Додано коректні constructor-конфіги AuthFeature/NodeAuthFeature, усунуто
  конфліктні barrel exports, відновлено імпорти external license types та
  опис фактичного AMD define API встановленого Ace.
- У спільному billing-коді прибрано затінення error-ref та небезпечне
  використання незавантаженого Stripe. Невідома ціна показується як «—»;
  додаткові платіжні сценарії не перевірялися живою транзакцією.
- Сценарій локальної збірки перевіряє справжній запуск Python, підтримує
  -PythonExe / FRE_LAUNCH_PYTHON, зберігає freeze lockfile і встановлює лише
  desktop dependency closure, без непотрібного postinstall вебсайту Nuxt.

Перевірки цього етапу:

- Python **5/5**: повний pipeline на чистому реальному pin, невірний SHA,
