# FRE LAUNCH 0.5.7 Alpha — Minecraft Launcher

**Your Minecraft. Your Rules.** Неофіційний лаунчер Minecraft Java Edition для Windows 10/11 x64. Стек: Tauri 2, Rust, React, TypeScript.

## Два інсталятори — який вибрати?

Відкрий [GitHub Actions](https://github.com/Freeze0102/FRE-LAUNCH/actions), обери останню **успішну** збірку **Windows Build** для `main`, прокрути до **Artifacts**.

- **FRE-LAUNCH-Windows-Installer** — рекомендований інсталятор **для поточного користувача**, не повинен вимагати права адміністратора.
- **FRE-LAUNCH-Windows-Admin-Installer** — альтернативний інсталятор, дозволяє встановити для всіх користувачів, вимагає UAC/права адміністратора.
- **FRE-LAUNCH-Windows-Portable** — EXE без інсталяції. Налаштування та Minecraft все одно зберігаються в даних користувача Windows.

Архів Artifacts — це ZIP. Його треба розпакувати перед запуском EXE.

### Встановлення на диск D:

У стандартному інсталяторі можна вибрати папку **`D:\FRE LAUNCH`**, якщо є дозвіл Windows на запис. Не встановлюй безпосередньо в корінь `D:\`. Якщо раніше використовував системний інсталятор, спочатку закрий усі вікна FRE LAUNCH.

Під час CI стандартний інсталятор не тільки збирається, а й запускається в тихому режимі із власною тимчасовою директорією на Windows runner. **Це перевірка лише на конфігурації GitHub, не доказ успішного встановлення на конкретному диску користувача.**

Папка встановлення EXE та папка гри — різні речі: **Minecraft, світи та ресурси можуть і далі зберігатися в AppData на диску C:**. Їх не можна переносити простим переміщенням інстальованого EXE.

## Як запустити Minecraft

1. На сторінці «Профілі» створи офлайн-нікнейм.
2. На сторінці «Версії» обери Vanilla (для першої перевірки краще звичайний release).
3. Натисни **Встановити / перевірити** або кнопку на головній.
4. Після справжнього завершення завантаження натисни **Грати зараз**.
5. Для Vanilla 1.21.4 потрібна Java 21. У параметрах є виявлення і менеджер Java.
6. Для Fabric/Quilt та модів створи окрему збірку й вибери сумісний модлоадер.

Offline-профіль не обходить серверну перевірку придбаної ліцензії Minecraft.

## Якщо натискання «Встановити» призводить до помилки

**У самій програмі:** FRE LAUNCH 0.5 записує початок і результат встановлення до локального журналу, не дозволяє кілька одночасних встановлень і перехоплює частину внутрішніх помилок Rust. Відкрий **Діагностика** → **Читати журнал** → **Копіювати помилки**. Якщо інтерфейс був пошкоджений помилкою React, з'явиться екран відновлення з можливістю перезапустити вікно й скопіювати помилку.

**У зовнішньому Windows-інсталяторі:** внутрішній журнал FRE LAUNCH ще не створений. Використай стандартний неадміністративний інсталятор замість адміністративного, спробуй каталог у своїх правах доступу, наприклад `D:\FRE LAUNCH`. Якщо Windows інсталятор закривається без повідомлення, шукай помилку через Windows Event Viewer → Windows Logs → Application.

Повний виліт операційної системи, сторонній антивірус або несправний диск не можна виправити лише React-кодом.

## Захист встановлення та перевірка Minecraft 1.21.10
- Перед початком завантаження лаунчер перевіряє **вільне місце на тому диску, де зберігається Minecraft**, а не тільки диск зі встановленим FRE LAUNCH. Рекомендовано мати не менше 900 МБ.
- Тимчасові мережеві помилки Mojang/CDN та невірний SHA-1 повторно перевіряються до трьох спроб. Вже правильно завантажені файли залишаються в кеші після перезапуску.
- Одночасне завантаження ресурсів обмежено, а розпакування native-бібліотек має ліміти для захисту від надмірного використання пам'яті та диска.
- GitHub Actions додатково перевіряє **справжні метадані та ресурс версії 1.21.10** з офіційних серверів Mojang.
- Якщо Windows аварійно закриває сам процес лаунчера, журнал може не містити винятку. Подивись у Windows **Перегляд подій → Журнали Windows → Програма**, події Application Error / Windows Error Reporting для `fre-launch.exe`; у «Діагностиці» FRE LAUNCH скопіюй звіт.

## Якщо FRE LAUNCH закривається під час натискання «Встановити»

Нова сторінка **«Завантаження» / FRE DOWNLOAD ENGINE** показує місце зберігання Minecraft і результат перевірки доступу до диска. Перед встановленням лаунчер пробує записати тимчасовий файл у каталог гри; якщо немає доступу, показує пояснення замість початку завантажень.

Відкрий **«Діагностика»**, натисни **«Читати журнал»**, скопіюй записи `INSTALL_START`, `INSTALL_TARGET`, `INSTALL_STAGE`, `INSTALL_ERROR` або `INSTALL_PANIC`. Так можна встановити останній успішний етап перед збоєм. Файли журналу зберігаються локально, автоматичних відправлень немає.

**Місце встановлення FRE LAUNCH на D: і каталог Minecraft — різні речі.** Гра використовує стандартну папку даних користувача Windows. Кінцевий тест на конкретному комп'ютері все ще потрібний.

## Windows Error Reporting

У розділі «Діагностика» FRE LAUNCH читає локальний звіт Windows Error Reporting про власний процес `fre-launch.exe`, якщо Windows його зберегла. Звіт містить тип аварії та модуль помилки. **Нічого не надсилається автоматично**, не потрібні права адміністратора. Якщо WER-звіту немає, відкрий **Win+R → `perfmon /rel`**, знайди аварію FRE LAUNCH та скопіюй її технічні деталі.

## FRE LAUNCH 0.5.2 — цілісність інсталяції

- Виправлено перевірку статусу встановлених ігрових файлів: відсутній чи пошкоджений Minecraft client, бібліотека або індекс ресурсів тепер змінює статус на «не встановлено» й запускає ремонт при спробі гри.
- Файли старих Maven-бібліотек без SHA-1 повинні мати справжній ZIP/JAR-заголовок, а не випадковий HTML від сервера.
- CI перевіряє SHA-1 **повного клієнтського Minecraft JAR, реальної бібліотеки та ресурсу** з офіційного Mojang CDN. Це не гарантує відсутності вильоту на конкретному ПК.
- Оновлено GitHub Actions до Node 24-compatible action versions, прибрано попередження про Node.js 20.

## Вбудовані оновлення — FRE LAUNCH 0.5.3+

Через ~10 секунд після відкриття FRE LAUNCH перевіряє **GitHub Releases**. Якщо існує новіша версія, у лівій панелі з'являється «НОВА ВЕРСІЯ». Відкрий розділ «ОНОВЛЕННЯ», обери свій режим встановлення (**Для мене** або **Для всіх, з правами адміністратора**) й підтвердь дію. Лаунчер сам завантажує Windows-інсталятор, перевіряє його **SHA-256** за файлом з того самого офіційного GitHub Release, запускає інсталятор і закривається. Світи та налаштування при звичайному оновленні не видаляються.

**Важливо:** контрольна сума SHA-256 захищає від пошкодження файлу та розбіжності із GitHub Release, але **це не незалежний цифровий підпис видавця**. Ніхто не має встановлювати невідомі інсталятори з іншого сайту. Кожна наступна версія потребує збільшення версії у package.json, Cargo.toml та tauri.conf.json — GitHub Actions автоматично публікує новий Release після успішної Windows-збірки main. Опублікований реліз не перезаписується.

Для версій 0.5.2 і старіших потрібне **одне останнє ручне встановлення 0.5.3**: у них ще не існує механізму оновлень.

## Якщо лаунчер закривається через дві секунди

У версії 0.5.3 запускаємося завжди з головного екрана, не відновлюємо останню важку вкладку. Three.js/3D скіни завантажуються тільки під час входу до скін-студії. Після раннього закриття на наступному запуску автоматично активується **RECOVERY** — програмне малювання WebView2 без GPU-прискорення. Якщо лаунчер працює 20 секунд без аварії, спеціальний маркер відновлення зникає.

Якщо навіть у RECOVERY лаунчер знову закривається: Win+R → perfmon /rel → вибери аварію FRE LAUNCH → «Технічні відомості», і передай код помилки / назву модуля. Це важливо: збірка CI не може відтворити краш конкретного драйвера або інсталяції Windows.


Recovery тепер зберігається між запусками та використовує окремий локальний кеш WebView2. Якщо RECOVERY допоміг і хочеш повернути апаратне прискорення, у «Параметри» є кнопка повторного ввімкнення GPU (потрібен перезапуск). Вона не видаляє світи.

## FRE LAUNCH на справжньому коді Modrinth (без окремих гілок)

У гілці **main** підключено офіційний Modrinth App як Git-підмодуль `vendor/modrinth`, зафіксований на коміті `4ccf4d51804627cd0687ce7dfd5004f20c267acc`. Повний вихідний код приходить із Modrinth через `git submodule update`; це не HTML-макет і не копія, вручну перемальована в React.

**Дії на Windows, без GitHub Actions:**

1. Встанови Git, Python 3 з командою `py`, Node.js 24.15+, pnpm 12.11+, Rust та Windows C++ Build Tools із компонентами WebView2 / Tauri.
2. Отримай репозиторій командою `git clone --recurse-submodules https://github.com/Freeze0102/FRE-LAUNCH.git` або завантаж ZIP з GitHub та розпакуй його. Скрипт сам завантажить зафіксований код Modrinth, якщо ZIP не містить підмодуля.
3. Перейди в папку FRE-LAUNCH і запусти `powershell -ExecutionPolicy Bypass -File .\FRE-MODRINTH-LOCAL.ps1 -BuildWindows`.
4. Скрипт копіює зафіксований Modrinth у `FRE-Modrinth-Source`, робить ребрендинг, прибирає хостинг і рекламні екрани та викликає Windows NSIS збірку. Це відбувається **локально**, без хвилин GitHub Actions.

Для підготовки вихідного коду без збірки прибери `-BuildWindows`.

Попередній FRE LAUNCH React залишається у `main`, його файли й Minecraft-світи не переписуються. Новий код має окремий ідентифікатор `app.frelaunch.modrinthfork`, і профілі старого лаунчера автоматично не переносяться.

**Статус:** вихідний код Modrinth підключено. Під час локальної підготовки додаються профілі за ніком у Rust/SQLite та Vue, окремий Microsoft-вхід і завершення 159 відсутніх українських рядків (англійська залишається запасною). Перед збіркою запускається `scripts/modrinth-fork/verify.py` для перевірки вихідного коду, ключів перекладу та формату UUID. Інсталятор `.exe` **ще не зібраний та не перевірений**, отже запуск Minecraft і Microsoft-вхід на Windows наразі не підтверджені. Локальний нік не надає ліцензії та не дозволяє входити на сервери з перевіркою Microsoft.

**Покращення FRE LAUNCH:** на стартовому екрані з’являється поле для локального ніку; після створення профілю список акаунтів має оновлюватися без перезапуску. Локальний нік також завершує початковий крок вибору Minecraft-профілю, не підміняючи Microsoft-авторизацію. На сторінці скінів для локального акаунта відображається пояснення та вимикається застосування скіна через Minecraft Services. Додано українську назву стартового екрана та доступні українські підписи. Папка `packages/app-lib/.env` створюється з публічних налаштувань Modrinth, щоб не блокувати Rust/Vite збірку.

**Підхід до розвитку:** сучасна кодова база Modrinth уже містить бібліотеку збірок, імпорт, синхронізацію game options, ресурс-паків, менеджер завантажень, налаштування Java, журнали й перегляд скриншотів. Першочерговий пріоритет — перевірка запуску, сумісності локальних профілів, захист світів і діагностика помилок, а не дублювання готових функцій.
