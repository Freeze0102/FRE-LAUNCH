# Minecraft на Rust як частина FRE LAUNCH

## Результат

Тепер активний код FRE LAUNCH використовує власний плагін **`fre-rust`**,
а не `fre-horizon`. У бібліотеці можна створювати і бачити свої
Rust-профілі, а кнопка «Грати» запускає **`fre-rust-client.exe`**
без відкриття іншого лаунчера та без передачі команди `horizon-launcher play`.

Розділ називається **Minecraft на Rust**, доступний у тому самому майстрі
створення збірок. Під час запуску FRE LAUNCH перевіряє
Microsoft-акаунт, що володіє Minecraft: Java Edition, і передає його
сесію ігровому клієнту **через stdin, а не через аргументи чи файл**.
Офлайн-нік для Java-збірок не замінює цей обов'язковий власницький вхід.
Повторний запуск тієї самої Rust-збірки в одному процесі FRE LAUNCH
блокується, щоб захистити світи.

Світи та налаштування Rust-профілів ізольовані в
`%APPDATA%\app.frelaunch.modrinthfork\fre-rust-minecraft\profiles\`.

### Звідки береться ігровий рушій?

Готовий Minecraft-клієнт на Rust — це великий окремий ігровий проєкт.
Для наявної реалізації береться **відкритий код нативного клієнта** з
https://github.com/horizon-rust/horizon, MIT-ліцензія, авторство і
`LICENSE.txt` зберігаються у збірці. **Це не власноруч написаний із нуля
движок FRE LAUNCH.** Використовується саме вихідний Rust-код клієнта,
**не** оригінальний Horizon Launcher. Через таку архітектуру в UI та в
запуску немає залежності від його застосунку.

Minecraft і приватні ресурси Mojang/Microsoft мають інші права.
Їх не можна просто брати й додавати до публічного інсталятора для всіх.
Вони готуються локально з власної гри користувача. **Не публікуйте
інсталятор із чужими або власними пропрієтарними ресурсами Minecraft.**

## Як створити власний локальний білд із Rust-грою

Потрібні Windows x64, Visual Studio C++ Build Tools, Rust MSVC,
Git, Java, Node 24.15+, pnpm 12.11.2+ та **законно встановлена
Minecraft: Java Edition 26.3, запущена хоча б раз**.

У PowerShell у каталозі FRE LAUNCH:

```powershell
.\BUILD-FRE-RUST.ps1 -MinecraftDir "$env:APPDATA\.minecraft"
.\FRE-MODRINTH-LOCAL.ps1 -BuildWindows
```

Якщо `horizon-prepare` не може автоматично знайти потрібний pinned
server JAR, вкажіть **свій легально отриманий** `-ServerJar "ШЛЯХ"`.
Сценарій збірки не підміняє відсутніх залежностей, не обходить акаунти
і зупиняється при помилці.

Сценарій компілює саме ігровий двійковий файл Rust та утиліту
підготовки ресурсів з **закріпленої ревізії вихідного коду**. Він кладе
`fre-rust-client.exe` і підготовлені ресурси у локальну тимчасову
папку `scripts/modrinth-fork/fre-rust-runtime/`. Потім локальна збірка
FRE LAUNCH пакує їх як ресурси Tauri (лише для особистого використання).

Папка внесена в `.gitignore`, щоб приватні матеріали, сотні мегабайт
ресурсів Minecraft і скомпільований клієнт не потрапили на GitHub.

## Що не зроблено

- Не зібрано новий Windows EXE в цьому сеансі та не проведено запуск гри.
  Додавання коду в GitHub саме по собі не встановлює новий клієнт на ПК.
- У публічному релізі без дозволених Minecraft-ресурсів Rust-гру не можна
  відразу запускати. UI перевіряє наявність клієнта і ресурсів, не
  показує удаваного успіху.
- Внутрішній рушій усе ще походить із відкритого MIT-проєкту. Повністю
  незалежний, з нуля переписаний Minecraft на Rust — значно більший
  окремий проєкт із рендерером, мережею, світом, блоками й механіками.
- Старі Horizon-профілі не видаляються, але **не імпортуються автоматично**:
  нова бібліотека використовує свої профілі. Це не дає випадково
  пошкодити наявні світи.

## Цілісність Rust-гри

Під час локального пакування перевіряються MIT-ліцензія, pinned-коміт
`975c07d9151847e6af13afc4b5ab37b6bbe78ef5`,
відсутність символьних посилань у ресурсах і SHA-256 клієнта.
Перед запуском FRE LAUNCH повторно перевіряє SHA-256 за локальним
`BUILD-INFO.json`. Це **перевірка цілісності, не незалежний цифровий підпис**.

Закріплений Rust-рушій містить upstream-виправлення солом'яного ліжка
(PR #3954) та використання предметів під час відкриття інвентарю
(PR #5511). Роботу нотних блоків та інші ігрові відмінності ще потрібно
перевірити у Minecraft 26.3. Статичні тести коду не замінюють
внутрішньоігрових тестів.

## Перевірки без GitHub Actions

Генератор має точні перевірки прив'язки до pinned Modrinth-форка.
Rust-обробник також має тести валідації ID профілю, назв і відсутнього
клієнта, щоб не оголошувати порожній runtime готовим.
**Локальна компіляція Rust/Vue і тест реальної гри ще потрібні.**
GitHub Actions не запускалися.
