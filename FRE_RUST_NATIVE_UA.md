# Minecraft 26.3 на Rust у FRE LAUNCH

FRE LAUNCH містить власну копію повного відкритого Rust-джерела
[horizon-rust/horizon на коміті 975c07d9151847e6af13afc4b5ab37b6bbe78ef5](https://github.com/horizon-rust/horizon/tree/975c07d9151847e6af13afc4b5ab37b6bbe78ef5).
У `vendor/fre-rust-source` перенесено всі 4174 файли з цього коміту, MIT LICENSE,
сторонні ліцензії та тести. Це звичайні файли цього репозиторію, не submodule.
Маніфест імпорту дозволяє перевірити кожен Git blob і повне дерево
`85268b86aaa57415fbb2c8d784d7a375b4b44d82`.
Upstream-джерело не змінене. Бінарний Horizon Launcher не збирається й не запускається.

Починаючи з 0.5.11, перед компіляцією `native_branding.py` створює власне дерево
FRE у `.audit/fre-native-source/current`: назви вікон і завантаження, іконки,
Rust-компоненти, Java-пакети, журнали та ресурсні файли узгоджено перейменовані.
Інсталятор містить лише цю збірку FRE. Початковий snapshot у `vendor` і юридичні
повідомлення збережені для перевірки походження й дотримання MIT.
Чужий Discord application ID і надсилання upstream-телеметрії вимкнені.

Для вже створених підписаних пакетів збережено читання старих назв маніфестів
модів, модпаків і шейдерів. Архіви, підписи й авторські дані не переписуються.
Нові налаштування та встановлені файли використовують назви FRE. Перед
пакуванням обов'язково проходять тести ядра, preparer, форматів модів і шейдерів;
неперевірений або застарілий runtime не потрапляє до інсталятора.

Наявні власні налаштування й папка модів перейменовуються без перезаписування
конфліктних файлів. Міграція перевіряє блокування відкритих світів; `level.dat`
не переписується. Старий кеш ресурсів перебудовується під нові імена з уже
завантажених офіційних Minecraft-файлів і JDK. Резервні копії залишаються на диску.

## Використання

1. У FRE LAUNCH увійди через Microsoft в акаунт, який володіє Minecraft Java Edition.
2. Створи звичайну збірку, вибери завантажувач **Rust** і Minecraft **26.3**.
3. FRE LAUNCH створить окремий профіль та відкриє його сторінку.
   Перший запуск завантажує перевірені файли Mojang у приватний кеш застосунку,
   за потреби встановлює Eclipse Temurin JDK 25 і запускає свій вбудований
   нативний підготовлювач ресурсів.
4. Натисни **Грати**. Сесія Minecraft передається клієнту через приватний stdin,
   без токенів у командному рядку чи метаданих профілю.

Horizon Launcher, його акаунт і попередньо встановлена Java/Minecraft не потрібні.
Офлайн-нікнейм Java-профілю не замінює перевірку володіння грою.
Підготовлені ресурси можна також імпортувати з локальної папки.

Профілі відображаються у спільній бібліотеці, групуванні, виборі та швидкому
перемиканні. Є перейменування, вибір і скидання іконки, підтверджене видалення,
перегляд файлів/світів/логів і локальний імпорт `.hmod`.
Java JAR-моди Fabric/Forge та нативні кодові `.hnmod` тут не встановлюються.

**Налаштування → Встановлення → Перевірити й відновити файли гри**
перевіряє спільний кеш. Пошкоджені незавершені кеші зберігаються під іншою назвою;
світи профілю не перезаписуються. Перевірка враховує версію формату ресурсів,
позначку preparer, основні файли й хеші, а перед запуском виконує його `--check`.
Нативний рушій оновлюється разом із перевіреною збіркою FRE LAUNCH. Ця збірка
підтримує тільки зафіксовану Minecraft 26.3; нові версії потребують перегляду джерела.

Mojang може перевидавати маніфест 26.3 для нових перекладів.
Downloader використовує точний маніфест за його зафіксованим SHA-1, тому така
зміна не блокує чисте встановлення і не підміняє перевірені файли новішими.

## Клієнтські моди FRE LAUNCH

Відкрий Rust-збірку → **Моди**. Вбудовані моди показані в тому самому списку,
що й установлені пакети:

- **Зум**: за замовчуванням увімкнений, утримуй **C** для плавного наближення
  **4×**, відпусти для звичайного огляду. Можна вибрати **2×–10×** і клавішу
  **C**, **V** або **Z**. Чутливість миші під час наближення зменшується.
- **Лічильник FPS**: компактна панель кадрів за секунду.
- **Координати**: постійні **X / Y / Z** без F3.

FPS і координати спочатку вимкнені. Увімкнення, сила зуму й клавіша зберігаються
окремо для кожної збірки. Закрий гру перед зміною; нові значення діятимуть
після наступного запуску. Зум не працює поверх меню або підзорної труби.
F1 ховає панелі, а F3 звільняє місце для штатного екрана налагодження.

Ці три моди вже скомпільовані в перевірену гру FRE LAUNCH; встановлювати Rust
або окремий лаунчер не потрібно. Імпорт власних `.hmod` доступний у меню **⋮ → Додати з файла**. Налаштування містяться у `fre-client-mods.json` у папці збірки; світи
під час їх зміни не переписуються.

## Каталог модів і перевірка файлів — 0.5.14

Натисни **Моди → Додати моди**, щоб відкрити живий список з публічного реєстру:
пошук за назвою, автором і тегами, тип пакета, опис, версія для Minecraft 26.3,
ліцензія та кнопка переходу до вихідного коду на GitHub. На момент перевірки
реєстр містив **94 проєкти**: 85 нативних модів, 3 пакети модів, 1 ресурс-пак
і 5 шейдерів. Кількість і версії можуть змінюватися.

Натискання картки відкриває вкладки **Опис**, **Версії** й **Результати
перевірки**. Кнопка **Установити** сама перевіряє підтриманий пакет і встановлює
його після успішної перевірки; перевірка також виконується для кожного
стороннього `.hmod` перед запуском гри. Перевіряються:

- HTTPS-джерело та належність GitHub release до проєкту/реєстру;
- свіжий список відкликаних версій, розмір і SHA-256;
- підпис, якщо автор його надає, за зафіксованим у FRE публічним ключем;
- маніфест, версія, тип вмісту, шляхи, розміри архіву та текстур;
- завершене сканування Microsoft Defender і незмінність файла після нього.

Змінений/новий ключ автора, невідповідний хеш, відкликання, небезпечна структура
або незавершене антивірусне сканування блокують установлення. Відсутність підпису
показується окремим застереженням. Без свіжого реєстру зовнішні файли не
встановлюються й не запускаються; три вбудовані моди та профілі без `.hmod`
не потребують цього з’єднання. Збережений каталог доступний для перегляду.
Локальний імпорт приймає лише перевірені пакети даних; сторонній виконуваний
код і файли іншого формату не активуються.

**Межі:** проходження цих перевірок не є гарантією безпечності мода або повним
аудитом його коду. Нативні `.hnmod` показуються та перевіряються, але потребують
окремої переглянутої сумісної збірки FRE; їхній код не компілюється й не
запускається автоматично. Варіанти зуму, FPS та XYZ уже доступні у списку
модів збірки як вбудовані моди FRE. Ресурс-паки й шейдери наразі доступні для перегляду.

Кнопка **Установити** доступна для підтриманого пакета даних API 0.2,
який пройшов перевірки. Це може бути лише ресурсна частина нативного мода;
залежність вказана в описі. Minecraft-функції пакета можуть змінювати світ.
Непідтриманий формат не означає знайдений вірус: наприклад, пакет із NBT
відхиляється через відсутність окремого валідатора цього формату.

Файли надходять із GitHub без акаунта іншого лаунчера. Оригінальні назви
маніфестів і посилання зберігаються для перевірки підписів та походження.

## Зручне керування модами — 0.5.14

Rust-профіль використовує ті самі `ContentCardTable`, `ProjectCard`, пошук,
перемикачі, меню та вікна, що й звичайні збірки. На основній сторінці — лише
встановлені та вбудовані моди; повторний файловий список прибраний.

- **Додати моди** відкриває окремий каталог. Кнопка повернення веде до списку
  збірки; відкриття й закриття картки зберігає пошук і сторінку результатів.
- Є пошук установлених модів за назвою, автором і файлом, фільтр, сортування,
  вибір кількох рядків, групове ввімкнення/вимкнення й підтверджене видалення.
- У меню **⋮ → Додати з файла** можна вибрати кілька `.hmod` одразу.
- Зум налаштовується через його меню **⋮ → Налаштування мода**.
- Каталог підтримує сортування, список/сітку та сторінки по 20/40/80 записів.
  Вбудований варіант FRE відкривається кнопкою **У збірці**.

Перемикачі пакетів змінюють справжній `fre-mods.txt`, який читає гра.
Кнопка встановлення та імпорт увімкнуть підтриманий пакет для наступного
запуску; додатково заходити в налаштування модів самої гри не потрібно.
Увімкнення повторює захисні перевірки; невдала перевірка залишає пакет вимкненим.
Інші налаштування, клавіші та світи не переписуються. Під час гри зміни
заблоковані. Межі сумісності нативного коду, пакетів-компаньйонів, NBT,
ресурс-паків і шейдерів залишаються описаними вище.

## Збірка з цього репозиторію

Потрібні Windows x64, Rust MSVC / Visual Studio C++ Build Tools, Node 24.15+,
pnpm 12.11.2+, Python 3.11+ і Pillow 11–12. Джерело Modrinth зафіксоване
submodule-комітом `4ccf4d51804627cd0687ce7dfd5004f20c267acc`.

```powershell
# Перевірити повноту й точний вміст вбудованого MIT-джерела:
python scripts/modrinth-fork/native_source.py vendor/fre-rust-source

# Побудувати гру, preparer і Windows-інсталятор без updater-публікації:
.\BUILD-FRE-WINDOWS.ps1 -Preview

# Для підписаного updater-артефакту використовується ВЖЕ НАЯВНИЙ ключ каналу:
.\BUILD-FRE-WINDOWS.ps1
```

Обидва варіанти використовують один пакувальник, перевіряють обидві EXE за SHA-256
і додають MIT-ліцензію та повні джерела експортерів, потрібні preparer.
Перевірений runtime повторно використовується без перекомпіляції.
Жоден сценарій не публікує реліз і не запускає GitHub Actions.
Важкі Windows-workflow запускаються вручну.

Minecraft JAR, текстури, звуки, ресурси, токени та згенеровані експортери
**не включаються** в Git чи інсталятор. Вони створюються тільки на ПК власника.
Інсталятор не є заявою про повну відповідність усіх механік Minecraft:
перенесено конкретний експериментальний upstream-коміт.

Клієнтські моди 0.5.12, результати тесту зуму та хеші інсталятора: [звіт](VALIDATION_CLIENT_MODS_2026-11-05.md).
