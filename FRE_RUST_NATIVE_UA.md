# Minecraft 26.3 на Rust у FRE LAUNCH

FRE LAUNCH містить власну копію повного відкритого Rust-джерела
[horizon-rust/horizon на коміті 975c07d9151847e6af13afc4b5ab37b6bbe78ef5](https://github.com/horizon-rust/horizon/tree/975c07d9151847e6af13afc4b5ab37b6bbe78ef5).
У `vendor/fre-rust-source` перенесено всі 4174 файли з цього коміту, MIT LICENSE,
сторонні ліцензії та тести. Це звичайні файли цього репозиторію, не submodule.
Маніфест імпорту дозволяє перевірити кожен Git blob і повне дерево
`85268b86aaa57415fbb2c8d784d7a375b4b44d82`.
Upstream-джерело не змінене. Бінарний Horizon Launcher не збирається й не запускається.

Починаючи з 0.5.11, перед компіляцією `native_branding.py` створює власне дерево
FRE у `.audit/fre-native-source/current`: назви вікон і завантаження, іконки,
Rust-компоненти, Java-пакети, журнали та ресурсні файли узгоджено перейменовані.
Інсталятор містить лише цю збірку FRE. Початковий snapshot у `vendor` і юридичні
повідомлення збережені для перевірки походження й дотримання MIT.
Чужий Discord application ID і надсилання upstream-телеметрії вимкнені.

Для вже створених підписаних пакетів збережено читання старих назв маніфестів
модів, модпаків і шейдерів. Архіви, підписи й авторські дані не переписуються.
Нові налаштування та встановлені файли використовують назви FRE. Перед
пакуванням обов'язково проходять тести ядра, preparer, форматів модів і шейдерів;
неперевірений або застарілий runtime не потрапляє до інсталятора.

Наявні власні налаштування й папка модів перейменовуються без перезаписування
конфліктних файлів. Міграція перевіряє блокування відкритих світів; `level.dat`
не переписується. Старий кеш ресурсів перебудовується під нові імена з уже
завантажених офіційних Minecraft-файлів і JDK. Резервні копії залишаються на диску.

## Іконки встановлених модів — 0.5.17

Для відомого пакета список установлених модів показує назву, автора й іконку
з локального каталогу. Це працює для вже встановлених версій: перевстановлювати
моди не потрібно. Архів зі зміненим SHA-256 не отримує іконку іншого випуску.
Невідомі локальні пакети без каталожної іконки мають стандартну заглушку.

У звичайних Java-збірках Modrinth перевірка нових версій автоматична,
а встановлення підтверджується через **Оновити** або **Оновити всі** у вмісті.
[Результати перевірки 0.5.17](VALIDATION_NATIVE_ICONS_2026-11-07.md).

## Переносима EXE та сумісність модів — 0.5.16

Оновлену `FRE LAUNCH.exe` можна переносити окремо. Вона містить усі потрібні
MIT-файли нативної гри й автоматично відновлює їх у власний кеш, якщо поруч
немає папки `fre-rust` або вона пошкоджена. Світи й налаштування профілів
залишаються у своїй бібліотеці. Приватні Minecraft-ресурси до EXE не включені.

У каталозі натисни **Установити**: FRE вибере сумісну, не відкликану версію.
Для AppleSkin зараз використовується **0.1.2** від soufi: версія 0.1.3
потребує новішого API. Якщо сумісного випуску немає або перевірку не пройдено,
лаунчер покаже причину. Після вибору модів натисни **Грати** для їхньої
автоматичної збірки; перша компіляція може тривати багато хвилин.

Результати справжнього встановлення, переносимого запуску та роботи AppleSkin
у світі наведені у [звіті 0.5.16](VALIDATION_NATIVE_RECOVERY_2026-11-06.md).

## Використання

1. У FRE LAUNCH увійди через Microsoft в акаунт, який володіє Minecraft Java Edition.
2. Створи звичайну збірку, вибери завантажувач **Rust** і Minecraft **26.3**.
3. FRE LAUNCH створить окремий профіль та відкриє його сторінку.
   Перший запуск завантажує перевірені файли Mojang у приватний кеш застосунку,
   за потреби встановлює Eclipse Temurin JDK 25 і запускає свій вбудований
   нативний підготовлювач ресурсів.
4. Натисни **Грати**. Сесія Minecraft передається клієнту через приватний stdin,
   без токенів у командному рядку чи метаданих профілю.

Horizon Launcher, його акаунт і попередньо встановлена Java/Minecraft не потрібні.
Офлайн-нікнейм Java-профілю не замінює перевірку володіння грою.
Підготовлені ресурси можна також імпортувати з локальної папки.

Профілі відображаються у спільній бібліотеці, групуванні, виборі та швидкому
перемиканні. Є перейменування, вибір і скидання іконки, підтверджене видалення,
перегляд файлів/світів/логів і локальний імпорт `.hmod`.
Java JAR-моди Fabric/Forge не сумісні з Rust-клієнтом. Підтримані нативні `.hnmod` завантажуються з каталогу й збираються у FRE перед запуском.

**Налаштування → Встановлення → Перевірити й відновити файли гри**
перевіряє спільний кеш. Пошкоджені незавершені кеші зберігаються під іншою назвою;
світи профілю не перезаписуються. Перевірка враховує версію формату ресурсів,
позначку preparer, основні файли й хеші, а перед запуском виконує його `--check`.
Нативний рушій оновлюється разом із перевіреною збіркою FRE LAUNCH. Ця збірка
підтримує тільки зафіксовану Minecraft 26.3; нові версії потребують перегляду джерела.

Mojang може перевидавати маніфест 26.3 для нових перекладів.
Downloader використовує точний маніфест за його зафіксованим SHA-1, тому така
зміна не блокує чисте встановлення і не підміняє перевірені файли новішими.

## Моди та зум — 0.5.15

Відкрий **Уміст → Додати моди**. Кнопка **Установити** завантажує підтриманий
пакет прямо до цієї збірки, перевіряє його та вмикає для наступного запуску.
Вибери всі потрібні моди й натисни **Грати**: FRE сам збере ввімкнені нативні
моди разом. Окремий лаунчер, його акаунт або системна установка Rust не потрібні.

Перша нативна збірка завантажує приватний Rust **1.99.1** і MinGW із перевіркою
закріплених SHA-256. Лаунчер показує підготовку компілятора, залежностей,
поєднання модів, компіляцію та антивірусну перевірку. У повному тесті Fullbright
цей шлях тривав близько дев’яти хвилин; час залежить від комп’ютера та мережі.
Готова перевірена збірка повторно використовується, а вихідна гра залишається
окремо. Зміна набору модів підготує відповідний варіант перед наступним запуском.

Три моди вже вбудовані й не потребують додаткової компіляції:

- **Зум:** утримуй **C** й крути коліщатко, щоб плавно змінювати наближення
  під час гри від **1× до 64×**. Відпускання клавіші повертає звичайний огляд.
  У **⋮ → Налаштування мода** можна змінити початкове наближення **2×–10×**
  і клавішу **C / V / Z**. Чутливість миші зменшується відповідно до наближення;
  коліщатко під час зуму не перемикає слот панелі предметів.
- **Лічильник FPS:** компактна панель кадрів за секунду.
- **Координати:** X / Y / Z без F3.

Зміни цих вбудованих налаштувань застосовуються під час гри без перезапуску.
F1 ховає панелі, F3 звільняє місце для штатного екрана налагодження. Зум
не діє поверх меню та підзорної труби. Налаштування кожної збірки зберігаються
у `fre-client-mods.json`; світи не переписуються.

Пошук, сортування, вибір кількох модів, групові дії та підтверджене видалення
використовують ті самі компоненти, що й звичайні збірки. Дані `.hmod` формату
0.2 можна також імпортувати через **⋮ → Додати з файла**. Завантажені моди
змінюються після закриття гри; вбудовані налаштування залишаються доступними.

## Перевірка сторонніх модів

Перевіряються HTTPS-джерело GitHub release, свіжі відкликання, розмір і SHA-256,
підпис за закріпленим ключем автора, маніфест, сумісність, шляхи та межі архіву,
завершене сканування Microsoft Defender і незмінність файла після перевірки.
Готовий нативний EXE теж сканується й отримує хешований запис збірки.
Перед запуском перевіряються фактично ввімкнені нативні пакети та їхні записи.

Відкликання, підміна хешу/ключа, небезпечна структура або незавершене
антивірусне сканування блокують установлення чи запуск. Відсутній підпис
показується окремо. Нативний код працює з правами користувача: ці перевірки
**не гарантують безпечності** та не замінюють перегляд його коду.

Підтримані нативні моди використовують ігрові hooks зафіксованого рушія.
Пакети з додатковими crates, виконуваними кроками збірки, змінами компілятора,
цілями поза ігровим модулем або новішим API залишаються заблокованими з причиною.
Старі виконувані `.hmod` / WASM не активуються. Ресурс-паки й шейдери в цьому
каталозі поки доступні для перегляду. Деяким пакетам даних потрібен сумісний
нативний мод-компаньйон; дивись опис автора.

## Світи, сервери, журнали та час гри

**Уміст** підсвічується одразу після відкриття збірки. На Rust-сторінці
показується Microsoft-акаунт без зайвого перемикача збереженого профілю;
для Java вибір акаунта та нікнейма розділено зрозумілими кнопками.

**Світи** показує картки світів і збережених серверів, пошук, фільтри та
оновлення статусу. **Додати сервер** записує його у справжній `servers.dat`.
Кнопка **Грати** відкриває вибраний світ або приєднується до вибраного сервера
через нативний quick play; Rust-ID не передається Java-менеджеру збірок.
Підтримується саме Minecraft 26.3, сумісність сервера все одно потрібна.

**Журнали** використовує спільну консоль із живим оновленням, пошуком,
фільтрами рівнів і розгортанням. Доступні `latest.log` та датовані `.log.gz`.
Вивід обмежений останніми рядками; архіви розпаковуються потоком із межею
розміру. Журнали не надсилаються зовнішньому сервісу автоматично.

Час гри й дата останнього запуску зберігаються окремо для кожної збірки.
Поки лаунчер працює, час оновлюється в інтерфейсі й записується кожні 30 секунд
та після виходу гри. Старий час до цієї версії не вигадується. Завершення
самого лаунчера припиняє його відстеження дочірнього процесу.

Кнопка **Зупинити** червона. Верхня панель теж показує запущену Rust-збірку,
дозволяє зупинити її та перейти до журналу. Зупинка стосується лише процесу,
який запустив FRE; для збереження останніх змін світу краще вийти через меню гри.

## Збірка з цього репозиторію

Потрібні Windows x64, Rust MSVC / Visual Studio C++ Build Tools, Node 24.15+,
pnpm 12.11.2+, Python 3.11+ і Pillow 11–12. Джерело Modrinth зафіксоване
submodule-комітом `4ccf4d51804627cd0687ce7dfd5004f20c267acc`.

```powershell
# Перевірити повноту й точний вміст вбудованого MIT-джерела:
python scripts/modrinth-fork/native_source.py vendor/fre-rust-source

# Побудувати гру, preparer і Windows-інсталятор без updater-публікації:
.\BUILD-FRE-WINDOWS.ps1 -Preview

# Для підписаного updater-артефакту використовується ВЖЕ НАЯВНИЙ ключ каналу:
.\BUILD-FRE-WINDOWS.ps1
```

Обидва варіанти використовують один пакувальник, перевіряють EXE та інструменти збірки за SHA-256
і додають MIT-ліцензію та повні джерела експортерів, потрібні preparer.
Перевірений runtime повторно використовується без перекомпіляції.
Локальні сценарії не публікують реліз і не запускають GitHub Actions.
Важкі Windows-workflow запускаються вручну.

Minecraft JAR, текстури, звуки, ресурси, токени та згенеровані експортери
**не включаються** в Git чи інсталятор. Вони створюються тільки на ПК власника.
Інсталятор не є заявою про повну відповідність усіх механік Minecraft:
перенесено конкретний експериментальний upstream-коміт.
