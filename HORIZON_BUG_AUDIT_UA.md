# Аудит багів Horizon (Minecraft 26.3 на Rust)

Дата перевірки: 2026-11-01. Офіційний проєкт: https://github.com/horizon-rust/horizon
Перевірений стан `main`: tree `965fee125c417ad154074f4f64bc1d3fc9321b60`
(це **орієнтир для аналізу**, upstream часто оновлюється).

Цей файл описує **код гри Horizon**, не механіку Java Minecraft і не
Tauri-оболонку FRE LAUNCH. Жоден ігровий EXE не зібраний.

## 1. Солом’яне ліжко (Straw Bed) після сну

- Репорт: https://github.com/horizon-rust/horizon/issues/3132
- Статус офіційного репорту: **закрито як виправлений 2026-10-30**.
- Виправлення: https://github.com/horizon-rust/horizon/pull/3954
- Код `crates/horizon-client/src/game/beds.rs` у `free_left_beds`
  перевіряє `minecraft:straw_bed` і після пробудження в Overworld викликає
  `destroy_straw_bed`. У `respawn_anchor.rs` є окрема поведінка для
  використання ліжка в інших вимірах.
- У звіті наведено реальний внутрішньоігровий тест: на старій збірці v0.2.96
  ліжко лишалося, на `c3db4a6` руйнувалися обидві половини без дропа.
- **Висновок:** не переписувати вже виправлену логіку в FRE LAUNCH.
  Потрібно встановити сучасний реліз/нічну збірку Horizon і перевірити
  використання солом’яного ліжка у новому тестовому світі.
- У Nether/End та при смерті/виході під час сну потрібні додаткові тести.
  Солом'яне ліжко не має вибухати як звичайне ліжко — очікується руйнування.

## 2. Їжа/використання предмета при відкритому інвентарі

- Репорт: https://github.com/horizon-rust/horizon/issues/4472
- PR з виправленням і parity-тестом:
  https://github.com/horizon-rust/horizon/pull/5511
- Статус PR на час перевірки: **відкритий**, не злитий.
- Відтворення: почати їсти яблуко -> натиснути E в середині використання ->
  інвентар відкритий -> перевірити, чи предмет витратився і чи використання
  вчасно завершилося. Порівняти саме з vanilla Minecraft 26.3.
- Правильне виправлення має працювати у фазі **відкриття екрана клавішею**
  (інвентар, чат, досягнення), а не безумовно при кожному GUI/паузі.
  В PR #5511 є додаткові перевірки й окремий vanilla harness.
- Місця: `crates/horizon-client/src/game/remote.rs`,
  `crates/horizon-client/src/game.rs`,
  `crates/horizon-client-input/src/interaction_input.rs`.
- **Висновок:** не додаємо свій спрощений патч, який помилково скасовує
  використання й під час паузи або відкриття контейнерів. Такий патч
  тимчасово створювався, але був **прибраний** до релізу з репозиторію FRE LAUNCH.
  Чекаємо результату перевірки upstream PR або тестуємо його у відокремленому
  checkout, без модифікації інстальованої гри/світів.

## 3. Нотний блок (Note Block)

- Переглянуто:
  `crates/horizon-world/src/level/interact.rs`: `Class::Note`
  збільшує `note` і запускає `note_play`;
  `crates/horizon-world/src/level/redstone.rs`:
  `note_play`, `note_trigger_event`, реакція на redstone;
  `crates/horizon-client/src/game.rs`: звукові й particle події.
- На основі переглянутого коду **не доведено**, що звичайний нотний блок
  загалом не працює. Не можна чесно позначити цей баг виправленим або
  впроваджувати випадкове виправлення без відтворення.
- У загальному реєстрі незакритих прогалин є особливий випадок
  `NoteBlock.getCustomSoundId` із головою моба/гравця над нотним блоком:
  https://github.com/horizon-rust/horizon/issues/3516 .
  Цей реєстр може відставати від поточного коду, тому потрібна перевірка у грі.
- Тест для звичайного блоку: поставити на землю, тричі натиснути ПКМ без
  предмета в руці, потім подати сигнал redstone й порівняти ноти/звуки
  з vanilla 26.3; повторити з блоком над нотним блоком і з черепом.

## 4. Підхід до зменшення багів

1. Спочатку перевіряти офіційні issue/PR і останню версію Horizon:
   не відновлювати старі баги, уже виправлені upstream.
2. Для нових розбіжностей створювати мінімальне відтворення на чистому світі
   та порівнювати 26.3 vanilla і Horizon за однаковими діями.
3. Міняти лише вузьке місце логіки, додавати regression test і проганяти
   відповідний differential harness. Вимога upstream:
   `python3 tools/pr_ready.py`, `cargo fmt`, `clippy`, тести crates.
4. Не вважати статичні рядкові перевірки, зелений CI і високі % parity
   доказом відсутності всіх багів. Статус `833 gaps` у README — аудит
   методів, не точний лічильник відтворених багів.
5. Не змінювати наявні світи та інстальований `Horizon.exe`. Новий Rust
   виконуваний файл можливий тільки після окремої збірки джерел Horizon з
   власними ліцензійними Minecraft-ресурсами.

## Перевірено у цьому проході

- Прочитано обробники солом’яного ліжка, нотного блока, використання їжі
  та мережеве керування предметами в актуальному коді Horizon.
- Звірено статуси issues #3132, #4847, #4472, PR #3954, PR #5511.
- Надто широкий експериментальний патч використання їжі прибраний із
  FRE LAUNCH; він **не застосовувався до гри**.
- **Не зроблено:** збірка Horizon, запуск vanilla/Horizon, вимірювання FPS,
  кількості реальних багів чи зміна офіційного upstream. GitHub Actions
  FRE LAUNCH не запускалися.

Для наступної внутрішньоігрової перевірки достатньо записати:
точну версію Horizon (головне меню), ОС, кроки, expected/actual,
`%APPDATA%\horizon\logs\latest.log` (без токенів/приватних даних).
