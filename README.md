## Що таке FRE LAUNCH?

FRE LAUNCH — десктопний лаунчер із темним інтерфейсом, бібліотекою окремих збірок і каталогом модів. Мета — встановлювати Minecraft, керувати світами та ресурсами й запускати гру з одного місця.

| Можливість | Поточний стан |
|---|---|
| Vanilla Minecraft Java Edition | Встановлення з Mojang та запуск через Java |
| Бібліотека збірок | SQLite, окремі папки, RAM, Java, обране |
| Fabric / Quilt | Підготовка профілю для запуску; Quilt — експериментальний |
| Modrinth | Пошук із сортуванням, сторінки проєктів, вибір сумісних версій і модлоадера |
| Fabric-моди | Встановлення з Modrinth, обов'язкові залежності, SHA-512 і ручна перевірка доступних оновлень |
| Ресурс-паки | Перевірене встановлення ZIP, перелік, вимкнення та видалення з бібліотеки збірки |
| CurseForge | **Лише перехід до пошуку на сайті**; немає інтегрованого встановлення |
| Власні моди | Можна скопіювати `.jar` у `mods` обраної збірки |
| Світи, скриншоти, резервні копії | Локальне керування |
| Акаунти | Офлайн-нікнейми; Microsoft device-code → Xbox/XSTS → Minecraft-профіль **реалізовано у вихідному коді**, але потрібен схвалений Minecraft Client ID; Minecraft-токен у пам’яті Rust, ключ оновлення в Windows Credential Manager, автоматичне відновлення сесії |
| Шейдери | Встановлення сумісних ZIP у `shaderpacks`, керування в бібліотеці. Для роботи потрібен Iris або інший шейдерний завантажувач |
| Модпаки | Каталог і встановлення з Modrinth; імпорт локального `.mrpack` через Windows-файловий діалог (Vanilla/Fabric/Quilt, експериментально) |
| Forge / NeoForge | Ще не реалізовано |

### Інтерфейс, натхненний Modrinth App

**Поточна відповідність екранів і список функцій, яких ще бракує:** [MODRINTH_PARITY.md](MODRINTH_PARITY.md). Це реалізація на власному React/Rust-коді, а не збірка з чужого застосунку.

Компонування зорієнтоване на Modrinth App: вузька бічна панель із піктограмами, динамічна головна сторінка популярних проєктів, вкладки Modpacks/Mods/Resource Packs/Shaders, пошук списком, картка проєкту з відформатованим Markdown, сумісними версіями й окремою бібліотекою. Ігрові Minecraft-сервери (BedWars, SkyWars, Survival тощо) **залишаються**: можна зберігати IP, перевіряти статус і копіювати адресу. **Hosting / оренду серверів не додаємо.** Серверна авторизація й автоматичне підключення не підтримуються. Експериментальне встановлення опублікованих .mrpack із Modrinth тепер реалізоване для Vanilla, Fabric і Quilt: воно перевіряє SHA-512 та створює новий профіль. Пакети Forge/NeoForge і деякі зовнішні джерела ще не підтримуються; локальний імпорт .mrpack доступний через «Імпортувати .mrpack» у Play, Discover або майстрі створення збірки. Windows-збірка цієї зміни поки не перевірена.

**Важливо:** це окрема реалізація FRE LAUNCH, а не копія кодової бази чи брендових ресурсів Modrinth App. Джерело контенту — Modrinth API, який вказує авторство самих модів. Оформлення та логіку FRE LAUNCH можна змінювати у `src/`.

**Оновлення коду від 24.10.2026 не пройшли повне тестування Windows-компіляції.** Спершу виконай `npm run check` і `cargo test --manifest-path src-tauri/Cargo.toml` перед запуском свіжих змін. GitHub Actions навмисно вимкнено для автоматичних пушів через вичерпану квоту.

### Модпаки та скіни після аналізу коду Modrinth

Вихідний код Modrinth App вивчено у відкритому репозиторії Theseus. Формат .mrpack базується на офіційному `modrinth.index.json` з полями `files`, `hashes`, `downloads`, `env`, `dependencies` та папками `overrides` і `client-overrides`. Власний Rust-інсталятор FRE LAUNCH використовує тимчасову папку, перевіряє джерела HTTPS, хеші, ZIP, перевіряє JAR і створює нову збірку. У разі помилки намагається прибрати нову неповну збірку, не чіпаючи існуючі світи.

Локальна галерея скінів не рівнозначна встановленню скіна на Minecraft-акаунт. У скінах тепер є окрема дія «Застосувати до Minecraft-акаунта» для справжньої Microsoft-сесії: Rust надсилає PNG до офіційного Minecraft Services, а токен не передається в React. Без схваленого Minecraft Client ID або без активної сесії ця дія недоступна; вона не змінює скіни на серверах зі сторонніми плагінами. Підтримуються тільки PNG 64×64 / 64×32 для відправлення до Minecraft Services.

Поточний код ще **не підтверджено повною компіляцією на Windows** і не перевірено на реальних модпаках або Minecraft-акаунті. Деталі й відмінності від Modrinth: [MODRINTH_PARITY.md](MODRINTH_PARITY.md).

### Імпорт готової збірки Modrinth

Відкрий Play → **Імпортувати .mrpack** (або Discover → **Імпортувати .mrpack**, або «+» → Імпорт з комп'ютера), вибери завантажений локальний файл `.mrpack`. FRE LAUNCH зчитує файл без надсилання всього архіву до браузерного інтерфейсу, перевіряє маніфест `modrinth.index.json`, хеші завантажень та дозволені шляхи, застосовує `client-overrides` поверх `overrides`, створює **новий** профіль Minecraft й відкриває його у бібліотеці.

Це експериментальна функція. Forge/NeoForge, невідомі зовнішні джерела файлів і деякі великі модпаки наразі блокуються замість неповної інсталяції. Перед тестуванням зроби резервну копію важливих світів. **Реальне встановлення на Windows і запуск гри ще не підтверджені.**

### Швидкий локальний акаунт за ніком

У правому верхньому куті лаунчера натисни свій нік → **«Додати акаунт за ніком»** → введи 1–16 латинських літер/цифр/символів `_` → **+**. Обліковий запис зберігається в SQLite; за повторного введення існуючого ніка вибирається збережений профіль. Його можна перемикати без перезапуску. Активне ім'я й вибір офлайн/Microsoft зберігаються у локальних налаштуваннях.

Як у TLauncher, таке створення акаунта за ніком є **офлайн-профілем**, а не Microsoft/Minecraft-ліцензією чи реєстрацією на ігровому сервері. Важливо: якщо обрано Microsoft-профіль без підтвердженої сесії, запуск гри тепер явно запропонує авторизуватися замість непомітного переходу на офлайн-нік.

Виправлена також гонка станів: миттєве завершення Java не повинно повертати кнопку «Грати» в хибний стан «Гра працює». Правильний статус визначає Rust-подія процесу.

### Вхід через Microsoft

У **новій тестовій збірці** кнопка «Увійти через Microsoft» відкриває браузер і показує одноразовий код. Звичайний користувач не має вводити Client ID, **але тільки після того, як розробник FRE LAUNCH отримає від Minecraft Services дозвіл на свій public Client ID** і вбудує його в збірку. Не копіюйте чужі Client ID.

Для розробника: створіть Microsoft Entra public app, дозвольте personal Microsoft accounts та device-code flow, отримайте дозвіл через [Minecraft app registration](https://help.minecraft.net/hc/en-us/articles/16254801392141), а тоді на Windows запустіть локальний скрипт із правильною змінною середовища:

```powershell
$env:FRE_MS_CLIENT_ID = "ВАШ-СХВАЛЕНИЙ-CLIENT-ID"
.\FRE-LAUNCH-LOCAL.cmd
```

Цей код потребує компіляції Rust і **не перевірений на реальному схваленому ID**. Реєстрація нового Microsoft-акаунта відбувається лише на [офіційному сайті Microsoft](https://signup.live.com/); FRE LAUNCH не повинен запитувати чи зберігати пароль.

### Вхід через Microsoft

У розділі **«Облікові записи»** є підключення через офіційний Microsoft device-code flow. Пароль вводиться лише на сайті Microsoft. Після успішних Xbox Live / XSTS / Minecraft Services етапів програма бере справжній Minecraft UUID, ім'я та токен у захищеному Rust-коді для запуску гри. Офлайн-профілі залишаються окремими.

**Для роботи входу потрібен власний Client ID**, налаштований як Microsoft public client і допущений Minecraft Services. Звичайний Entra Client ID без Minecraft-допуску може отримувати HTTP 403. Не використовуйте чужі Client ID або секрети. Після успішного входу Rust зберігає лише Microsoft refresh token у Windows Credential Manager та пробує автоматично відновити Minecraft-сесію після перезапуску. Пароль і Minecraft access token не зберігаються у localStorage чи конфігурації лаунчера. Відновлення не вдасться, якщо доступ відкликано, токен прострочено або Windows сховище недоступне. Без Client ID система не зможе виконати вхід, і ми не повинні показувати оманливе «Увійшов».

## Перші кроки

1. Відкрий **Бібліотека / Мої збірки** й створи збірку під потрібну версію Minecraft.
2. На сторінці збірки вибери **Vanilla**, **Fabric** або експериментальний **Quilt**, налаштуй RAM та Java.
3. Встанови Minecraft або запусти його з головної сторінки. Java має відповідати вимогам версії гри.
4. У **Каталозі модів** шукай проєкти Modrinth: пошук запускається після введення, є сортування й фільтр сумісності. Для Fabric-модів вибирай Fabric-збірку; лаунчер підбирає сумісну версію та потрібні залежності.
5. Для власного файлу відкрий **Мої збірки → Файли → Моди** та поклади `.jar` у `mods`. Він повинен відповідати версії Minecraft та модлоадеру.
6. Перемкни **Каталог модів → Моя бібліотека**, щоб вимикати, знову вмикати й видаляти файли модів, ресурс-паків та шейдерів у вибраній збірці. Для шейдерів спершу встанови сумісний Iris у Fabric-збірку.
7. Для Fabric натисни **Перевірити оновлення**, щоб побачити нові версії відомих Modrinth-модів. **Автоматичної заміни старих JAR ще немає**: перед ручним встановленням нового випуску вимкни старий, аби уникнути конфліктів.

> Папки `mods`, `saves`, `resourcepacks`, `shaderpacks` розташовані всередині окремої збірки, а не в корені `minecraft`. Датапаки для конкретного світу Minecraft зазвичай належать до `saves/<назва-світу>/datapacks`.

### Де зберігаються файли?

За стандартних параметрів Windows:

```text
%APPDATA%\app.frelaunch.desktop\
├── fre-launch.sqlite3       # Збірки й офлайн-профілі
└── minecraft\
    ├── versions\            # Версії Minecraft
    ├── libraries\           # Ігрові бібліотеки
    └── instances\
        └── <UUID збірки>\
            ├── mods\
            ├── resourcepacks\
            ├── shaderpacks\
            └── saves\
```

**Встановлення самого FRE LAUNCH на D: не переносить Minecraft з AppData автоматично.** Перед ручними операціями з каталогами роби резервну копію світів.

Журнал запуску гри зберігається в `instances/<UUID збірки>/logs/fre-launch-game.log`. Вивід Java пишеться у файл, а не в канали вікна лаунчера: це допомагає Minecraft продовжувати роботу після закриття FRE LAUNCH. Взаємодію з реальним Windows-процесом ще потрібно протестувати.

## Безпека модів

Для модів, ресурс-паків і шейдерів, встановлених через Modrinth, лаунчер перевіряє HTTPS-джерело, обмеження розміру та відповідність SHA-512, указаному сервісом. ZIP ресурсів і шейдерів також проходять перевірку вмісту та обмеження розпакування. Перед запуском також виконується **вбудований структурний аналіз JAR**: перевірка ZIP, CRC, небезпечних шляхів, деяких вкладених виконуваних файлів та обмежень на розпакування. Він застосовується і до власних JAR, покладених у папку збірки.

**Це не антивірус і не аналіз поведінки Java-коду.** Мод, який пройшов перевірки, усе ще може бути шкідливим. Не вимикай захист Windows лише заради встановлення, перевіряй репутацію автора, завантажуй із довірених джерел і зберігай резервні копії світів. Детальніше — [SECURITY_NOTICE.md](SECURITY_NOTICE.md).

## Для розробників

Вимоги: **Node.js 22**, **Rust stable**, Windows 10/11, **WebView2** та Microsoft C++ Build Tools для Tauri.

```bash
npm install
npm run check
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri build
```

Для локальної розробки:

```bash
npm run tauri dev
```

[Windows CI](.github/workflows/windows.yml) містить перевірку TypeScript, збірку фронтенду, Rust-тести та Windows-пакування. **Зелений workflow не підтверджує, що Minecraft реально запустився на твоєму комп'ютері.** Статус завжди перевіряй саме у **Windows Build**, а не у workflow очищення гілок.

### Відомі обмеження й статус випусків

- Повний тест встановлення, запуску Minecraft з модами та збереження параметрів на різних комп'ютерах **не завершений**.
- Офлайн-профілі не підтверджують ліцензію Minecraft та не замінюють авторизацію Microsoft.
- Деякі сервери мають власну реєстрацію; сам нікнейм не відновлює серверний акаунт.
- CurseForge потребує офіційного доступу до API для повної інтеграції.
- Публічний реліз **не схвалено до завершення розслідування спрацювання антивіруса**.
